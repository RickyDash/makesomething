# iOS Safari QA — real WebKit pass (simulator)

Companion to `design-qa.md`. That pass used Playwright viewport emulation in desktop Chromium; this one drives real iOS Safari in the simulator with HID taps (`idb`), production build (`npm run build && npm run start`, port 3000).

## Evidence

- Devices: iPhone 17 Pro, iOS 26.3 (402×874 CSS px, Dynamic Island, bottom Safari tab bar); iPhone SE 3rd gen, iOS 17.5 (375×667, home button). SE run has Settings → Accessibility → Reduce Motion **on**.
- Screenshots: `output/ios-simulator/iphone-17-pro/NN-*.png`, `output/ios-simulator/iphone-se-3/NN-*.png` (device pixels, 3x / 2x).
- Input: real touch events through `idb ui tap|swipe|multi-tap|rotate`; long-press = `tap --duration`. Timing-sensitive steps were scripted in one shell command because tool latency between steps is 10 s+.
- Pre-work: 17 code-level suspects were adversarially verified by a 58-agent read-only workflow before this pass; rows below say whether the simulator confirmed them.

## Severity

P0 blocks play · P1 clearly wrong for a normal player · P2 polish / edge case
